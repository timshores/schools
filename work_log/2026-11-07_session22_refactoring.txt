2026-11-07 (Session 22) - Explorer: Fixes and Refactoring from a Code Review

Tim (seahag prompt log #236, #237): a read-only review of mywebsite and this pipeline found about 50 refactoring
opportunities and a few bugs; Tim asked for all of them, in the order recommended (bugs, cleanups, a safety net,
then structural work), one item per push. This file records the pipeline's share.

Check used throughout: export_explorer_data.py takes a site root, so each change is exported to a scratch
directory and compared with the one before (each JSON file as data, meta.built dropped; each CSV as bytes). The
export reproduced the committed files exactly before any change.

1. Charter schools are not regional (A.2). The export called a district regional when its DESE code was 0600 or
   more; DESE numbers its newer charter schools from 3500, so 13 of the 72 current charter schools (Argosy
   Collegiate, Baystate Academy, ...) were flagged regional and given revenue series. The Census F-33 file has no
   Massachusetts charter school (its one 04xx row is Northampton-Smith, vocational), so every series was empty, and
   the explorer drew an empty revenue chart for those 13 where the other 59 said revenue isn't available; the
   charter average claimed 13 regional members. is_regional() now decides it in one place, charter schools
   excluded, at every test the export made by code (explorer_history.py already excluded them). Diff: only those
   13 districts' flags and empty series, and the charter average's rev_members (13 -> 0). Tim: charter schools
   stay their own category, and without revenue data whose provenance is clear, they have no revenue figures.

2. Data nobody reads (B.10). Removed from the export, each checked by grep against mywebsite's TypeScript and
   .astro files: rev_check (town-run districts' Census totals), towns' rev_total (spend_total stays: the map's
   spending per resident reads it), labor_latest (each town's, and the metadata's), and the averages' day_n
   (districts counted each year). explorer_history.drop_empty() leaves out a current district's or an average's
   series with no figure before FY2005 (spending by category, in- and out-of-district pupils, out-of-district
   payments: all null, since that history comes from DESE's day-program reports); former districts keep their whole
   records. districts-history/ 1.25 MB -> 0.72 MB; all explorer data 15.8 MB -> 15.1 MB. Check: every figure in
   the data before is in the data after, unchanged, except the four fields named; nothing added; the explorer's
   Since 1990 views (a district, two averages, a charter school, a comparison) render the same.
   Dead code: district_cache.py and generate_district_cache.py (imported by nothing; their cache read by nothing),
   with CACHE_DESIGN.md and CAGR_CACHE_DESIGN.md, which described them; URL_C70_WHITEPAPER; town_data's reg
   parameter (shadowed by a local of the same name).

3. A safety net (D.17). ppe_report/check_explorer_data.py: `shape SITE` (no NaN or infinity, which JSON.parse
   refuses; every series as long as its years: the explorer's 21 from FY2005, the history's 15 from FY1990, the
   day-program series' 17 to FY2006, a town's votes [held, won]; every district dict of series with one set of
   keys) and `diff BEFORE AFTER` (each JSON file as data, meta.built dropped; each CSV as bytes). The committed
   data passes; three faults planted in a copy (a short series, a NaN, a stray key) are each caught. To check a
   change to the export: export to a scratch directory, `shape` it, `diff` it against mywebsite. mywebsite gained
   unit cases for its number formats (in every build) and browser checks of the explorer (scripts/check/).

4. The pipeline restructured (C.16), output unchanged byte for byte at every step (check_explorer_data.py diff and
   shape; the export also compared with diff -rq against a baseline). explorer_common.py: what the export and the
   history pass share (years, ENROLL/NSS, REGIONS, EXCLUDE_DISTRICTS, slug, norm, series, pack, is_regional,
   with_functional, ood_per_pupil, and Hub, which lower-cases DESE's rows once, indexes each district's once and
   memoizes, so the history pass reuses the export's figures; history() takes 6 parameters, not 12).
   read_sources() reads each source once (population was read 7 times, the members file 5). One function each for
   total spending per pupil, the no-cap factor, required spending per pupil, levy room, vote kind. Writes go to
   staging directories swapped in at the end, so a failed run leaves the site as it was; check_inputs() fails on a
   missing input (every input is committed) where WARN let a run ship half its files. cache_manager.stale_sources()
   treats the cache as stale when it's older than its sources, and --force-recompute forces it (a fresh clone
   recomputes once: git leaves the sources a moment newer). get_enrollment_group: half-open ranges, raising on
   NaN or a negative value, where a value between ranges fell to SMALL. main 261 -> 39 lines, write_csvs 243 -> 14
   plus one function per file, map_data 226 -> 47, town_data 224 -> 28; a Group NamedTuple with its outlier flag.
   Source URLs in one SOURCE_URLS table. Export time 5:15 -> about 1:40 (explorer_districts 32 s -> 1.7 s,
   history 142 s -> 5 s). All 227 names other scripts import from the changed modules still resolve.
   Found on the way and fixed: towns-chapter70-targets.csv multiplied each town's yield by the targets' total in
   64-bit integers before dividing, which overflowed for Boston: its no-cap target read -$407,169,082 (FY2026) and
   -$347,580,589 (FY2027). It now takes the yield times the year's factor, as cap.json does: $1,047,625,653 and
   $1,077,801,854. Only those two rows change.
   Left: town_entities is the slowest step now (fiscal_series and property_series filter whole frames per town);
   the PDF side's prepare_western_epp_lines bucket mode still uses closed ranges; data/cache is tracked in git.
